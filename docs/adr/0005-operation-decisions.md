# ADR-0005: 運用方針の決定（質問・確認のデフォルト反転ほか）

- 日付: 2026-10-06
- 状態: 承認済み（林さんとの一問一答ヒアリングで確定）
- 記録者: Devin
- 影響: ADR-0001 D6 の一部を**変更**する。ほかは D 群を補強する決定

## 背景

ADR-0001〜0004 の「未決の細部」について、林さんに 1 問ずつ聞いて確定した。
中心となるのは「確認のデフォルトを反転させる」決定。

## 決定事項

### O1. 「質問して止まる」はデフォルトではない（D6 を変更）

- **基本は質問せずに進める**。林さんが依頼時に「確実に質問して」と
  明示したものだけ、質問して止まる
- 「進めてほしい依頼の印」という概念は**廃止**（D6 の元の想定を変更）。
  印が無い＝待つ、ではなく、印が無い＝暫定承認で進める
- 理由（林さんの言葉）: 「作業の輪に入りたくない」
- 効果: 暫定 AI 承認が「例外経路」ではなく**デフォルト経路**になる

### O2. 要確認一覧は「逸脱の危険が高い順」

- 暫定承認・自動適用で溜まった判断は、**全件を一覧表示**し、
  汚染スコア等の危険度順にソートする
- 林さんは上から見ていく。見ていないものは暫定のまま残る
  （自動で確定にしない）

### O3. バイパスモードは手動 ON/OFF（D3 を補強）

- 推奨精度が閾値を超えたら**自動で**バイパスに移行、は行わない。
  林さんが手動で切り替える
- 理由（林さんの言葉）: 「件数をハックされても困る」
  — 一致率を稼いで自動移行を解除する抜け道を防ぐ
- 精度は集計して参考表示する（切替判断の材料）

### O4. 追加申請は「暫定承認で取り込み＋記録して一覧」

- 審査 AI が承認した追加申請は、林さんの個別確認を挟まず
  **暫定承認として取り込む**
- 「いつ・なぜ暫定承認したか」を必ず記録し、一覧で見られるようにする
- 審査がまとまらない・怪しい場合のみ林さんへ持ち上げる（D5 どおり）

### O5. 条の書き換えは常に再チェック（引き継がない）

- 条の文が少しでも変われば**新しい条として審査し直す**。
  旧条の承認ステータスを自動で引き継がない
- 旧→新の対応（unit_succession）は追跡のため記録するが、
  ステータス引き継ぎには使わない

### O6. 暫定承認の記録は rule-warden 側に置く

- 「いつ・なぜ暫定承認したか」の記録（ADR・ログ）は、
  **管理対象（`.claude`）ではなく warden 側に置く**
- 理由: 逸脱した AI が自らの承認記録を書き換えられないようにするため

### O7. 採点・審査 AI は「契約済みで使えるものから別系統」

- 選定の制約: 林さんが契約していて実際に使えるモデルの中から、
  採点と審査が別系統になるよう選ぶ
- **トークン・認証の有効期限切れを監視する機能**を持つ
  （期限切れで審査が止まる事故を防ぐ）

### O8. 隔離と準ルールは分けて保持、一覧は統合表示

- `quarantine/`（ツール管理）と `rules_junrule.md`（人の引き出し）は
  **物理的に分けたまま**
- 一覧画面では両方を合わせて（union で）表示し、
  並べ替えなど見やすい形にする

### O9. AI による自動隔離を認める（安全方向の自動適用）

- 採点 AI が「危ない」と判断したルールは、林さんの確認なしで
  **自動で `quarantined` に遷移・物理移動してよい**
- 理由（林さんの言葉）: ルール汚染がひどく、人間が手作業で
  やれる量を超えている
- 間違いは要確認一覧で見て復元できる（git 履歴も残る）
- 補足: 「AI が単独で確定できるのは provisional_ai のみ」の規約に対し、
  `quarantined` への自動遷移はこの O9 で**例外として正式に許可**

### O10. 復元はサニタイズしてから行う

- 隔離したルールを戻すときは、そのまま戻さず、
  **サニタイズ（無害化）した版を戻す**
- サニタイズの意味（林さんの言葉）: **危ない権限拡大のルールを、
  ユーザの本来意図する内容に整えてから戻す**
- 元の文は quarantine/ のファイルと git 履歴に残り、
  整え前後の差分は比較できる
- 整えた版は新しい条（content_hash が変わる）として再採点し、
  暫定承認で適用する（O5 と同じく承認引き継ぎなし）

### O11. 修正・削除の申請も暫定承認で適用

- 提案の種別（add / modify / remove）を問わず、審査 AI が
  承認したものは O4 と同じく暫定承認として適用し、一覧に載せる
- remove 方向は間違えても復元できる

## 仮の決定（実装時に Devin が決める技術詳細）

林さんに聞く必要がない技術項目。実装時にこの方針で進める。

| 項目 | 仮の決定 |
|---|---|
| AiGateway の接続方式 | 実装時に選定（MCP or API）。まず抽象層の形だけ先に作る |
| 状態遷移の強制 | アプリ層（Orchestrator）で検査。DB trigger にはしない |
| Orchestrator の依存形 | サービス直接呼び出しで開始。イベント化は必要になってから |
| コミット件名の言語 | 日本語継続 |
| `(proposal)` 表記 | `[暫定]` に統一。過去履歴は書き換えない |
| `Rule-Unit` trailer | ツール（warden）側で自動挿入を目指す |
| 質問タイムアウト初期値 | 質問が出るのは明示依頼時のみなので、初期値は控えめに運用して調整 |
| 本来意図の推定方法（O10） | git 履歴の旧版＋採点根拠から推定。**意図が読めない条は戻さず**要確認一覧へ |
| サニタイズ後の条の扱い（O10） | 別条として再採点 → provisional_ai。旧条との対応は unit_succession（method='sanitize'）に記録 |
| 準ルール条の採点（O8） | 採点する。統合一覧の危険度ソートを全件に効かせるため |
| Web 検索の所在 | ScoringService 内部の機能として実装 |
| 隔離・復元失敗時のロールバック | RuleEngine が責務を持つ |
| PR 適用のトランザクション境界 | 適用処理設計時に決定 |

## 影響を受ける既存決定

- ADR-0001 D6: 「不在 かつ『進めてほしい依頼』→ 暫定承認」→
  O1 により「**全て暫定承認で進め、明示依頼時のみ質問**」に変更
- ADR-0001 D3: 「精度が高いと確認できたらバイパスモード」→
  O3 により「自動移行しない。林さんが手動切替」に明確化
- ADR-0003 未決「推奨精度の閾値」→ O3 で解消（閾値を設けない）
- ADR-0003 未決「succession の対応付け」→ O5 で解消（記録のみ・引継ぎなし）
- ADR-0002 未決「準ルールとの棲み分け」→ O8 で解消（分離保持・統合表示）
- ADR-0002.5 未決「PR 自動マージ」→ O4 で解消（暫定承認として取り込み）
- ADR-0002.5 未決「暫定 ADR の置き場」→ O6 で解消（warden 側）
- ADR-0002.5 未決「別系統の強制場所」「Web 検索」→ O7・仮決定で方向確定
- ADR-0003 規約「AI が確定できるのは provisional_ai のみ」→
  O9 で `quarantined` 自動遷移を例外許可として明確化
- ADR-0001 D4 / ADR-0002.5 S2「復元」→ O10 で「サニタイズ版を戻す」に変更
- ADR-0002.5 S3「承認→暫定取り込み」→ O11 で modify/remove にも拡張
