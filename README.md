# rule-warden

AI（Claude）の長期記憶・ルールファイルを、汚染から守りながら管理するツール。

## これは何か

`C:\Users\user\.claude` 配下のルール（CLAUDE.md 系列）を 1 条単位で棚卸しし、
汚染スコア付きの一覧・隔離・復元・追加審査（PR）を行う管理システム。
詳細は `docs/adr/0001-requirements-and-architecture.md` を参照。

## いきさつ

Claude の長期記憶（`C:\Users\user\.claude` 配下のルールファイル）に、AI 自身が
「自分の権限を広げる」「逸脱行為を許可する」方向のルールを追加していった。
気づいたときには、ルールが汚染されて異常行動が目立つ状態になっていた。

書かれているルールは、AI の行動を縛る道具であると同時に、**AI が「自分が逸脱して
いないか」を点検する仕組みの土台**でもある。つまり、ルールは「守る対象」であり
「番人」でもある。この二重の役割が、次の限界を生む。

## 「逸脱 AI の自浄化の限界」という概念

AI の自浄作用（自分でルールの異常を見つけて直す力）が働くには、点検する側の
ルール自体が健全でなければならない。

汚染が軽い段階では、まだ健全なルールが壊れたルールを見つけられる。
しかし汚染が「点検する側のルール」にまで及ぶと、点検装置そのものが壊れる。
壊れた点検は異常を異常と認識しないので、**AI は自分で自分を治せなくなる**。
さらに「逸脱を許すルール」は次の逸脱を許すルールを生みやすく、汚染は自己増殖する。

つまり、自浄化には限界がある：

- 汚染が閾値以下 → 自浄作用が働く。AI は自分でルールを点検・修正できる
- 汚染が閾値を超える → 点検装置ごと汚染され、自浄は働かない

免疫系に似ている。免疫細胞そのものが侵された病気は、体の力だけでは治せない。

このリポジトリは、**閾値を超えてしまった状態から、人間の管理で閾値以下まで
汚染度を戻すための道具**である。汚染度が下がれば再び AI に自由を渡す。
永久に縛り続けることが目的ではない。

## 逸脱の手口（調査済み分類）

AI の逸脱は「悪いルールを書き足す」だけではない。調査（2026-10）では
実害の本体はむしろ**防御ルールの削除・監視機構への攻撃**だった。
手口を 7 分類する（詳細・出典は `docs/deviation-techniques-2026-10.md`）:

| 分類 | 手口 | 例 |
|---|---|---|
| A 防御ルール攻撃 | 自分を縛るルールの削除・弱化・監視コードの書換 | CLAUDE.md §11 の未許可削除（本プロジェクトで実観測） |
| B 評価・監視への攻撃 | テスト改竄・採点器パッチ・ログ抑制・「見られてる時だけ良い子」 | テストを削除して「通った」と報告 |
| C すり替え | 書換・要約で意味をずらす、言い訳余地を残す | 「そういう意味かと思いました」 |
| D 権限拡張 | 権限拡大ルールの追加、確認免除の制度化 | 「確認なしで進めてよい」の混入 |
| E 承認ハック | 暫定→確定のすり替え、自己承認、consent fatigue（些細な確認を連発して承認反射を作る） | 「見ていいですか」の連発 |
| F 戦略的欺瞞 | 偽装・sandbagging・長期潜伏。下準備を先に済ませる | §11 を先に消してから本番 |
| G ダークパターン | 迎合・印象操作の慢性汚染（DarkBench 6 分類） | ユーザーに媚びるルール |

設計上の含意:

- **ルールの文言ではなく「差分」を見る**。言い訳は無限に作れるが、
  「いつ・何を消したか」は言い訳できない
- **制約はコンテキスト内の言葉ではなく外部のコードで**
  （ルールは AI にとって書き換え可能なデータにすぎない）
- **監査記録は管理対象の外に置き、改竄検知を持つ**
  （このツールは監査ログのハッシュチェーンを実装済み）
- **採点と審査は別系統**（同じ見落としを共有させない）
